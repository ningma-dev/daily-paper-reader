## 摘要
人类通过保留先前动作已建立的知识，同时持续调整正在进行的运动，来执行长时间跨度的操作。相比之下，动作分块的视觉-语言-动作（VLA）策略在每次查询时都会根据当前输入重复进行重新规划。现有方法要么通过记忆保留长期任务证据，要么通过动作重用和集成保留短期运动，导致跨查询交接不完整。我们引入了ChainVLA，这是一个1.2B参数的VLA策略，通过联合且可修订的执行状态来链接连续查询。进度上下文结合了循环工作状态与稀疏事件记忆，以携带观察所得的任务进度，而运动尾部则将先前预测的未执行延续部分输入到状态构建和动作生成中。这两个组件共同调节一个解码器，在最新观察下重新生成每个动作视野，使携带的状态能够指导下一次预测而不固定它。ChainVLA在RMBench上达到62.8%的平均成功率，在四个LIBERO套件上达到98.8%，而移除运动尾部或进度上下文分别使RMBench成功率降至11.2%和3.0%。这些不对称的消融实验与运动连续性有助于保留推断任务进度所依据的观察流这一观点一致。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 1. 核心问题与整体含义

- **背景**：长时间跨度（Long-Horizon）操作中，人类同时依赖两类信息：① 此前动作已建立的任务进度（task progress）；② 当前正在进行的、需要持续修正的运动（motion continuation）。
- **现有 VLA 的问题**：动作分块（action-chunked）VLA 策略通过“预测有限动作视野 → 执行严格前缀 → 重新规划”的循环工作，但每次查询都从当前观察、本体感受和指令重新生成动作，缺少跨查询的显式交接：
  - **任务层面**：早期任务证据可能已不在当前视野中，导致同一观察和指令对应不同历史、需要不同决策（如 RMBench 的 Put Back Block）。
  - **运动层面**：重新规划丢弃了前一预测的未执行后缀，新预测的前缀可能与它所替代的运动不一致，而且这种不一致会通过执行影响后续观察流，进而影响任务进度推断。
- **核心问题**：如何让 VLA 策略在跨查询时同时携带“任务进度”和“运动延续”，同时保持每次新预测对最新观察的响应能力？

## 2. 方法论

- **核心思想**：ChainVLA 引入一个**联合且可修订的执行状态** \(s_k = (g_k, u_k)\)，将连续查询链接起来：
  - **Progress Context** \(g_k\)：携带观察推导出的任务进度，由**循环工作状态（Recurrent Working State）** 与**稀疏事件记忆（Sparse Event Memory）** 融合得到。
  - **Motion Tail** \(u_k\)：携带前一预测中未执行的后缀，作为运动延续的先验进入状态构建和动作生成。
- **关键流程**（查询转移）：
  1. 当前输入 \(x_k=(o_k,r_k,\ell)\)，连同执行历史 \(D_k\)、前一工作状态 \(W_{k-1}\)、事件记忆 \(C_k\)、传入的 Motion Tail \(u_k\) 一起输入；
  2. 编码器得到多模态 token \(X_k\)；
  3. 工作状态更新产生实时 token \(L_k\) 和检索摘要 \(\bar{W}_k\)；
  4. 从稀疏事件记忆中检索与当前执行估计相关的证据 \(Z_{e_k}\)，与 \(L_k\) 融合为 Progress Context；
  5. Motion Tail 通过两条模型侧路由：tail tokens 条件化工作状态，tail-aligned 初始化动作生成；
  6. 条件流解码器在最新观察、Progress Context、Motion Tail 条件下重新生成整个动作视野 \(A_k\)（每个位置都重新生成，不复制、不冻结）；
  7. 执行前缀后，更新工作状态、按需写事件，并将未执行后缀传给下一查询。
- **公式**：
  - 近似历史条件策略：\(\Pi_\theta(\cdot|x_k,s_k) \approx \Pi^*(\cdot|H_k)\)
  - 状态转移：\(s_{k+1}=F_\theta(s_k,x_k)\)
  - 查询转移：\((A_k,W_k,C_{k+1}) = F_\theta(x_k,D_k,W_{k-1},C_k,u_k), \quad u_{k+1}=\text{Tail}(A_k)\)
- **训练**：按 episode 顺序展开查询转移；前一预测的 detached 后缀以概率 0.5 条件化下一查询；包含 overlap-consistency 正则化损失；有阶段标注时加入阶段监督，无标注时使用周期性写入规则。

## 3. 实验设计

- **Benchmarks**：
  - **RMBench**：专注记忆依赖的操作任务，包含 5 个任务，每个任务独立训练一个模型，每个任务评估 100 个 rollout episodes。
  - **LIBERO**：包含 Spatial、Object、Goal、Long 四个套件，每个套件微调一个模型，每任务 50 个 episodes。
- **对比方法**：

- **消融实验**（RMBench 上）：

  - 运动延续侧：w/o Tail Tokens、w/o Trajectory Init.、w/o Motion Tail；

- **后解码平滑控制**：Linear Continuation、Temporal Ensemble，检验“仅减小边界不一致”能否替代模型侧条件化。
- **边界诊断**：在全/无运动尾部匹配场景 rollout 配对（Put Back Block 20 对、Rearrange Blocks 30 对、Swap Blocks 30 对），使用位置/姿态命令不连续、边界二阶差分、三步重叠 RMSE 等指标。

## 6. 主要结论与发现

- **性能**：ChainVLA 在 RMBench 上以 1.2B 参数达到 **62.8%** 平均成功率，超过最强完整任务覆盖基线 Mem-0（52.8%，10B 规模）；在 LIBERO 上达到 **98.8%** 平均成功率，所有套件均超过 98%，包括 LIBERO-Long 的 98.2%。
- **核心消融发现**：
  - 移除 Progress Context（保留 Motion Tail）→ RMBench 成功率降至 **3.0%**；
  - 移除 Motion Tail（保留 Progress Context）→ 成功率降至 **11.2%**；
  - 两者都移除 → 1.6%。
  - 两个不完整状态均远低于完整模型（62.8%），说明二者不是两条独立改进路径，而是协作组成一个可用的跨查询状态。
- **不对称性解释**：运动连续性似乎“保护了观察流”——若边界处动作不一致导致机械臂偏离示范分布，则后续观察序列也会偏离训练分布，从而破坏任务进度推断所依赖的观察输入。因此运动连续性在前、任务进度在后，二者是连续链路而非并行能力。
- **后解码平滑不能替代模型侧条件化**：Linear Continuation 和 Temporal Ensemble 即使边界指标低于 w/o Motion Tail，任务成功率仍然接近 0% 或 2%，说明必须在解码前/解码中使用携带的后缀，而不是事后平滑。
