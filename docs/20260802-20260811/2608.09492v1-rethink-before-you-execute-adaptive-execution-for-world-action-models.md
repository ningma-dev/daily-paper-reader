## 摘要
世界行动模型（WAMs）联合预测未来行动与环境演变。在每次推理时，WAM生成一段行动，机器人执行一个固定前缀后才重新规划。我们认为，这种固定执行范围与执行动态并不匹配：片段可靠性在不同任务阶段存在差异，因此何时重新规划应取决于累积执行的结果，而非步数。我们提出TempoWAM（通过在线监控进度来定时执行），一种用于WAM的轻量级即插即用执行方案。一个循环进度监控器首先根据当前观测、任务指令、剩余行动和执行历史估计任务进度；随后，一个自适应执行协议评估该片段是否在推进任务，以决定是否需要重新规划。为弥合训练与部署之间的差距，该协议通过一个任务相关且在线自适应的校准因子进行校准。在LIBERO、RoboTwin和真实世界任务上的实验表明，TempoWAM持续改善了WAM执行的效率-成功权衡。在真实机器人上，它在简单任务上减少了26.9%的WAM推理次数，同时保持成功率，并在困难任务上将成功率提高了13.3个百分点。

## Abstract
World Action Models (WAMs) jointly predict future actions and the evolution of the environment. At each inference, a WAM generates a chunk of actions and the robot executes a fixed prefix before replanning. We argue that this fixed execution horizon is poorly matched to execution dynamics: the chunk reliability varies across task stages, so when to replan depends on the result of accumulated execution, not on the step counts. We propose TempoWAM (Timing Execution by Monitoring Progress Online), a lightweight plug-and-play execution scheme for WAMs. A Recurrent Progress Monitor first estimates task progress from the current observation, task instruction, remaining actions, and execution history; and an Adaptive Execution Protocol then evaluates whether the chunk is advancing the task to decide if replanning is needed. To bridge the training-deployment gap, the protocol is calibrated by a task-dependent calibration factor with online adaptation. Experiments on LIBERO, RoboTwin, and real-world tasks show that TempoWAM consistently improves the efficiency-success trade-off of WAM execution. On real robots, it reduces WAM inferences by 26.9% on easy tasks while maintaining success, and improves success by 13.3 points on difficult tasks.

# TempoWAM 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **研究对象**：World Action Models（WAMs，世界行动模型），这类模型联合预测未来动作与环境演变。
- **核心矛盾**：WAM 在每次推理时生成一段动作块（action chunk），机器人执行固定前缀后才重新规划。然而，**不同任务阶段的动作块可靠性并不一致**：
  - 简单阶段：动作块可持续保持准确很久；
  - 困难阶段：仅执行几步后误差便迅速累积。
- **核心批评**：固定执行视野（fixed execution horizon）与真实执行动态不匹配。何时重新规划应取决于**累积执行的实际效果**，而非预设的步数。
- **现有方法的不足**：已有自适应执行工作多依赖代理指标（如动作熵、预测一致性、注意力权重等），但这些指标并不显式衡量真正重要的事情——**任务是否在向前推进**。一个平滑的动作序列可能毫无进展，而高熵动作反而可能正在推进任务。
- **TempoWAM 给出的答案**：以**任务进度（task progress）** 作为自适应执行决策的自然判据，据此决定继续执行还是丢弃剩余动作并重新规划。

## 2. 方法论

### 2.1 核心思想

TempoWAM 是一个**轻量级、即插即用**的执行层方案，完全不需要修改或重训练骨干 WAM。它解决的核心问题是：**当前动作块剩余的部分还值不值得继续执行？**

### 2.2 总体架构（两大组件）

1. **递归进度监控器（RPM, Recurrent Progress Monitor）**：估计当前候选动作如果被执行，任务将达到的进度；
2. **自适应执行协议（AEP, Adaptive Execution Protocol）**：比较估计进度率与校准目标率，决定“继续执行”还是“丢弃并重规划”。

### 2.3 流程细节

- WAM 生成新动作块后，TempoWAM **先无条件执行一个短前缀**（长度 np，保证环境持续演化）；
- 之后每个决策步骤考察剩余动作块中接下来的 nt = min(np, |剩余动作数|) 个候选动作；
- 对这些动作评估：若任务仍在推进，则继续执行；否则丢弃余下动作，重新调用 WAM。

### 2.4 RPM 模块细节

- **输入**：当前观测、剩余动作候选、候选前缀长度 nt、上一进度估计 vt−1、任务指令。
- **观测编码**：复用 WAM 冻结的视觉骨干提取特征，经轻量 MLP 投影到监控器空间。
- **动作前缀编码**：用循环编码器处理候选动作，并加入前缀长度嵌入。
- **历史递归**：将上一进度估计注入学习投影，配合 GRU 聚合观测、动作、历史、位置嵌入。
- **预测头**：最终通过 MLP + sigmoid 输出 vt ∈ [0, 1] 的进度估计。

### 2.5 AEP 模块细节

- **核心比较指标——进度率**，而非绝对进度增量（因为同样增量在不同长度任务中含义不同）：
  - 当前进度率：ρcur = (vt − vt−1) / nt
  - 所需进度率：ρneed = max((1 − vt−1) / max(T̄ep − ut, nt), 0.2/T̄ep)
  - 原始比率：r̃t = ρcur / ρneed
- **校准因子 κ**（含离线和在线两个层次）：
  - **离线校准**：在演示轨迹上通过最小二乘拟合每集 κep，再取中位数得到任务级 κtask；
  - **在线适应（集内）**：用 EMA 更新 κ，补偿训练-部署差距；
  - **在线适应（集间）**：通过目标成功率调节缩放因子 δ′，成功率低于目标则更频繁重规划，高于目标则提升效率。
- **最终决策规则**：rt = r̃t / κfinal，rt ≥ 1 则继续执行，rt < 1 则重规划。

### 2.6 训练目标

- 监督标签为 yu = u/Tep（基于时间的任务进度）；
- 三个损失项：
  1. **BCE 进度预测损失**：对软进度标签做二分类交叉熵；
  2. **平滑性正则**：鼓励相邻进度估计的变化符合真实标签变化；
  3. **历史一致性正则（HCR）**：随机遮蔽部分观测后，惩罚遮蔽预测与原始预测的差异，促使监控器依赖执行历史而非瞬态视觉噪声。

## 6. 主要结论与发现

- **结论一**：固定执行视野在所有任务阶段上均非最优，自适应执行应以任务推进状态为准，而非代理指标。
- **结论二**：TempoWAM 在 RoboTwin 上，短视野任务保持或微升成功率并减少调用，长视野任务成功率提升（clean 86.93%→88.47%，randomized 84.47%→85.33%）且执行步数下降。
- **结论三**：LIBERO 上，成功率保持 97.25% 不变，WAM 调用从 14.88 降至 12.46。
- **结论四**：真实机器人上，简单任务（take drinks）WAM 调用减少 26.9% 且成功率不变；困难任务（pack hand cream）成功率从 50.0% 提升到 63.3%（+13.3 点）。
- **结论五**：跨骨干部署到 Motus 时无需重训练仍有效，move_can_pot 成功率最高提升 59 个百分点（从 35% 到 94%），表明进度驱动的自适应执行属于执行层能力，不依赖特定 WAM 架构。
- **结论六**：成功门控的集间调节因子 δ′ 能从统一初值出发，自动向各任务“目标成功率缺口”方向调节——简单任务放松以提升效率，困难任务收紧以恢复成功率。
- **结论七**：时间标签的有效性有条件——观测序列必须是“进度单调且无混叠”的；周期性或对称性任务会破坏监督信号。

## 7. 优点

1. **即插即用（plug-and-play）** ：不需要任何 WAM 骨干的修改或重训练，部署成本极低；
2. **进度驱动而非代理指标驱动**：直接估计“任务是否在推进”，比动作熵、注意力权重等方法更贴近执行决策的本质；
3. **极轻量**：2.27M 参数的监控器，单次决策成本仅为一次 WAM 调用的 3.54%（复用特征后低至 0.34%）；
4. **双向自适应能力**：在简单阶段延长动作块复用（提升效率），在困难阶段提前丢弃不可靠动作并重新规划（提升成功率），真正实现了“困难时多思考，简单时少思考”；
5. **双时间尺度校准机制设计巧妙**：离线条数 + 集内 EMA + 集间成功门控，从系统层面解决了训练与部署之间的分布偏移问题；
6. **分析严谨**：对时间标签的失效条件做了控制实验（回文序列构造），揭示了进度的视觉锚定特性，为后续工作提供了有价值的诊断结论。

## 8. 不足与局限

1. **时间标签的基础局限**：训练依赖 yu = u/Tep 的时间进度标签，在周期性、对称性或可逆任务上会因观测混叠而失效。论文仅对非重复性任务验证，尚未解决语义进度监督问题；
2. **真实实验规模偏小**：只有 3 个任务、每任务 30 次试验，统计功效有限，难以判断差异的显著性；
3. **跨骨干验证不足**：仅 FastWAM 和 Motus 两种骨干，且 Motus 上仅 2 个任务，RPM 直接迁移到其他架构（如视频生成式 WAM）的可靠性尚未验证；
4. **自适应基线对比不充分**：Auto-Horizon 和 AAC 仅在部分任务上做了对比，缺少全量任务上的系统性比较，且 AAC 的采样成本可能未被充分公平评估（虽然文中做了说明）；
5. **额外超参数增多**：引入了 np、np(候选)、EMA 系数、δ′ 初值、成功率目标 s∗ 等多个执行层超参数，实际部署中需要一定的调参成本；
6. **算力信息不透明**：未报告训练 RPM 所需的总 GPU 小时数、训练数据量等，限制了复现和成本评估；
7. **未考虑任务间泛化**：κtask 和 δ′ 是针对每个任务分别校准的，尚未验证跨任务共享校准机制的可行性。
