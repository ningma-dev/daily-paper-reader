## 摘要
视觉-语言-动作（VLA）模型直接将视觉观察和语言指令映射为机器人动作，但长时程任务需要的不仅仅是动作预测。随着物理状态的变化，智能体必须协调感知、规划、执行、进度验证和恢复。单独的动作预测或模型生成的技能决策，并不能保证所提议的操作在当前状态下有效，也不能保证其结果得到验证。我们提出EmbodiedSkills，这是一个统一框架，将每个技能决策视为执行提案：运行时在执行前检查其前提条件，并在事后验证结果。共享的可执行技能接口将高层技能选择、受限的低层VLA执行和动作后验证连接在一个智能体循环中。由于该接口保持不变，低层VLA策略可以在不改变智能体循环的情况下被替换或调整。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并在交互反馈可用时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务适应的低层VLA策略在50个RoboTwin 2.0任务中平均成功率达到86.20%，在四个LIBERO套件中平均成功率达到97.40%。这些结果确立了EmbodiedSkills中使用的任务适应的低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练和可检查的智能体层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 一、核心问题与研究动机

### 背景
- 视觉-语言-动作（VLA）模型直接将视觉观测与语言指令映射为机器人动作，近年来通过大规模预训练和多机器人数据采集表现出较强的任务泛化能力（如 π0.5、OpenVLA、Qwen-VLA 等）。
- 长时程操作任务远超"预测下一个动作"的范畴：机器人需要**感知场景 → 规划子目标 → 判断子目标在当前状态下是否可执行 → 调用低级 VLA 策略生成动作 → 验证效果 → 失败恢复**，即需要一个"智能体层（agentic layer）"。

### 核心问题
1. **动作预测 ≠ 有效决策**：仅靠 VLA 模型或 LLM 的技能提议，无法保证该操作在物理状态上"先决条件成立、执行后结果正确"。
2. **长程任务缺乏闭环验证**：端到端 VLA 模型把中间任务决策内隐化，失败后难以定位是目标定位、子目标选择、低级执行、进度验证还是恢复环节出问题。
3. **模型决策与物理执行之间存在断裂**：LLM-based 智能体虽能显式调用工具/技能，但无法强制约束该技能在当前状态下合法，也无机制验证物理结果。

### 研究目标
提出一个统一的、可训练、可检查、可部署的 VLA 智能体框架，将技能提议与运行时执行分离：**执行前检查前提，执行后验证结果**，使模型决策不会静默变成无效的物理动作。

## 二、方法论

### 核心思想

EmbodiedSkills 将每个技能决策视为一个**"执行提案"（execution proposal）**，由"高层级策略提出 + 运行时守卫"双层结构处理：

- **策略负责提议**：高层级 VLM 根据任务、观测和当前状态提出结构化技能调用/推进/终止等决策。
- **运行时负责裁决**：接收提议后先做阶段兼容性、输入齐备性、工件时效性、动作合法性和状态转移合法性检查，通过后才执行；执行后记录结构化轨迹供验证与训练。

### AgentLoop 的状态与决策

定义第 t 步方法级状态：

```
sₜ = (zₜ, Mₜ, Hₜ)
```

- zₜ：当前阶段
- Mₜ：任务工件集合（当前观测、感知结果、计划、活动子目标、执行报告、验证报告等）
- Hₜ：有序循环轨迹

高维策略的上下文为：

```
Cₜ = Ψ(x, zₜ, Mₜ, Hₜ)
```

智能体的结构化决策为三种控制类型之一：

```
dₜ ∈ { RunSkill(k, q), AdvanceStage, FinishRun }
```

即：执行某个技能、推进阶段或终止运行。

### 六个阶段（Phase-Structured Skill Space）

| 阶段 | 作用 | 关键输出 |
|------|------|---------|
| Observe | 获取当前视觉与任务证据 | 场景观测 |
| Plan | 将任务拆分为可验证的语义子目标 | 计划与活动子目标 |
| Preflight | 在执行前检查子目标是否可行（刷新证据） | 通过的就绪报告 |
| Execute | 生产并执行一个有界动作块 | 执行报告 |
| Verify | 用新证据判断子目标是否推进 | 进度判定 |
| Recover | 非可持续失败后的恢复/重规划 | 修订后的执行上下文 |

六个阶段不是固定流水线，而是由验证结果动态路由（Advance/Continue/Reobserve/Replan/Recover/Finish）。

### 可执行技能契约

每种可执行技能表示为：

```
k = (Xₖ, Yₖ, preₖ, execₖ, postₖ, failₖ)
```

- Xₖ/Yₖ：类型化输入/输出模式
- preₖ：前提条件
- execₖ：可执行操作
- postₖ：结果状态更新
- failₖ：失败状态与证据映射

该契约同时约束**模型级技能**和**确定性操作**，防止纯文本提议被直接当作物理状态转移。

### 守卫式运行时（Guarded Runtime）

对技能提议的守卫式检查为：

```
G_skill(sₜ, dₜ) = 1[dₜ = RunSkill(k, q)] · 1[阶段匹配] · 1[k ∈ 合法技能集] · ∏ 1[r(sₜ)=1]  (对所有前提 r)
```

对"推进阶段"的守卫为：

```
G_advance(sₜ, dₜ) = 1[dₜ = AdvanceStage] · 1[当前阶段已具备后继阶段所需证据]
```

终止使用独立控制门 `G_finish`。被守卫阻断的决策会作为显式证据记录在轨迹中。

### 有界动作执行（Bounded Action Execution）

在 Execute 阶段，低级 VLA 策略将活动子目标、当前观测、机器人状态、就绪证据映射为有限长度的动作块：

```
(gₜ, Oₜ, Fₜ) → aₜ → eₜ
```

动作块定义：

```
aₜ = (τₜ, Uₜ, Hₜ, ηₜ)，其中 Uₜ = [u¹ₜ, ..., u^Hₜ]
```

运行时只接受满足以下条件的动作块：时间范围在 H_max 之内、符合动作模式 Σp、与当前子目标/观测一致、数值有效。

### 验证与恢复

验证阶段仅基于**动作后的新证据**判断活动子目标的进展，输出语义路由：

```
V = {Advance, Continue, Reobserve, Replan, Recover, Finish}
```

恢复阶段使用相同的状态与失败证据生成修订后的上下文，同样经过运行时检查后再允许一次物理动作。

### 训练机制

1. **组件级监督适应**：规划器在任务指令+视觉上下文中训练生成语义子目标序列；低级 VLA 策略用"子任务级演示"单独微调；调度器在冻结低级 VLA 的条件下用部署一致的决策轨迹进行 SFT。
2. **部署一致的训练样本**：训练输入封装为 (g, zₜ, Iₜ, est, Kₜ, hₜ)，只包含部署时可用的信息，保证训练与推理时输入边界一致。
3. **可选的在线闭环优化**：记录完整交互轨迹，在环境评估器可用时可用 GRPO 风格的分组相对策略优化，但论文明确将其视为可选细化手段，不是主要结果来源。

## 六、主要结论与发现

1. **任务适应的低级 VLA 策略在 RoboTwin 2.0 达到 86.20% 宏平均成功率**，超越 LingBot-VA 参考的 π0.5（82.74%），高出 3.46 个百分点；主要增益集中在接触敏感型（Hanging Mug +20）和多阶段任务上（Blocks Ranking Size +15、Open Microwave +15）。
2. **LIBERO 四个套件平均成功率达 97.40%**，优于 OpenPI 参考（96.85%）；最大增益出现在 LIBERO-Long（+1.2 个百分点），说明该执行接口利于长序列场景。
3. **RMBench memory-dependent 任务仅 12.5%**，说明当前方法在"需要依赖先前交互历史"的场景下仍有明显限制。
4. **消融实验证明闭环三要素缺一不可**：去掉验证或语义子目标、或限制为单次 chunk，成功率分别从 86.20% 大幅降至 48.2%、34.4%、19.5%。合理有效的子目标分解本身不够，还需后置验证和自适应多 chunk 续行能力。

## 七、方法或实验设计上的优点

1. **将"提议"与"执行"分离**，由运行时守卫强制执行约束，使得非法模型决策无法静默转化为物理动作，失败类型在轨迹中可显式追溯。
2. **设计分层清晰**：六个阶段（Observe → Plan → Preflight → Execute → Verify → Recover）语义完整，不是固定流水线，支持动态回退和重规划。
3. **模块可替换性**：通过固定技能接口，低级 VLA 策略可以置换而不改变智能体循环，规划器/验证器/调度器可独立适配，这让组件级训练变为可能。
4. **训练与部署接口一致**：使用"部署一致性上下文"，不把模拟器专用信息或规划控制细节塞进高层策略，减小训练与推理的分布偏移；并且训练样本的构建遵循了部署时的历史压缩规则。
5. **消融设计清晰**：三个消融变量（有无 Verify、有无 Subtask、chunk 数限制）精确对应框架的三个核心设计选择，因果归因清晰。
6. **多 benchmark 验证**：RoboTwin 2.0（50 任务粒度比较）+ LIBERO（4 套件泛化）+ RMBench（记忆依赖）组合较全面地呈现了方法的适应性边界。
7. **诚实报告局限性**：论文明确承认 memory-dependent 任务准确率低、未做真实机器人验证等问题，没有回避框架在低层策略较弱的任务上的天花板。

## 八、不足与局限

1. **任务特化模型的开销问题**：论文自认 50 个任务各微调一个单独 π0.5 是 "specialist" 策略，训练、存储、部署成本远高于一个通用策略；该设定也让与通用模型的对比不那么公平。
2. **依赖底层组件质量**：运行时守卫只能挡"类型非法/缺前提"的决策，不保证语义正确的模型决策真的正确——错误的 grounding 或子目标只要满足模式/前提约束依然会被执行。
3. **验证能力受观测局限**：若任务进度被遮挡、视觉模糊或依赖不可观测属性（如力/触觉信息），验证器无法准确判断。
4. **真实世界缺失**：所有实验在仿真环境中完成，未做 sim-to-real 的迁移验证或真实机器人部署。
5. **RMBench 评估薄弱**：只有 4 个任务，且 12.5% 的低成功率表明对 memory-dependent 任务的代表性/深入分析不足，无法说明该框架在此类任务上到底差在哪里。
6. **无细粒度组件质量评估**：规划器、验证器、恢复策略各自单独好坏没有被独立评测，只有端到端消融的下游成功率间接反映。
7. **高计算与延迟开销**：额外的 VLM 调用和动作后验证引入显著延迟，长 episode 内容易累积小错误，导致"观察—重试—再调用"的轮次增加。
8. **在线自适应未充分实证**：文中第 4.3 节的 GRPO 型在线优化只是在方法论上提了方案，未提供相应实验数据支持。
9. **对比基准选择不够宽泛**：LIBERO 上只与 OpenPI 一组参考值对比；RoboTwin 上的 VLA baselines（π0/X-VLA 等）引用自其他文献而非本地复现，对齐条件存在不可控差异。
